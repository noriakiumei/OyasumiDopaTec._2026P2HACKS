# 009: 人の確認が要るときは、Discord のボットで本人に直接知らせる（MCP サーバー）

- 日付：2026-11-26
- 決めた人：（PR のレビューで決める。提案はいうてぃー）

## 決めたこと

- AI が人の確認を必要としたとき（マージ前のレビュー、「要相談」の判断）、Discord でその人をメンションしてレビュー依頼を送り、その件のスレッドを開く。返信は AI が読む。
- ボットは MCP サーバー（`tools/review-bot/server.mjs`、stdio）として出す。サーバーは立てず、各自のエージェントが手元で起動する。依存パッケージなし。
- GitHub のログイン名と Discord のユーザー ID の対応表は、トークンと一緒に `.env`（コミットしない）に置く。リポジトリは public なので、アカウントの対応を載せない。
- チームTast の Uni ボットは使わない（Uni はチームTast 専用）。

## 理由

- みんなが普段見ている Discord に本人宛てで届くので、レビュー待ちの時間がいちばん縮む。感想もその件のスレッドにまとまる。
- MCP の道具にすれば、Claude でも Codex でも同じように使える。AGENTS.md には「人の確認が要るときは本人に直接届く形で知らせる」という目的だけを書き、道具の名前は例として添える。
- 手元で起動する形なら、ホスティングやアカウントの準備が要らない。開発前の準備を増やさない。

## 検討したほかの案

- GitHub 連動（PR でレビューを頼むと GitHub Actions が Discord に投稿し、返信を定期的に PR のコメントに写す）：エージェントごとの設定が要らず、やりとりが PR に残る。ただし返信が写るまで15〜30分かかり、AI がスレッドに直接答えられない。chico の判断で MCP サーバーを選んだ。
- MCP サーバーをクラウドに常駐させる（Cloudflare Workers など）：トークンを配らずに済むが、ホスティングと認証の準備が要る。困ったら移す。

## 影響（変わること・注意すること）

- ボットのトークンをメンバーに配る。漏れたら Developer Portal で「Reset Token」して配り直す。ボットの権限はレビュー依頼のチャンネルだけに絞るとよい。
- クラウドで動くエージェントは、環境変数の設定と、ネットワークで `discord.com`・`gateway.discord.gg` の許可が要る。
- 通知が多いと無視されるので、気軽に呼ばない。小さな質問は PR・Issue のコメントで聞く。
