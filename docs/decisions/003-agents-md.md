## 決めたこと

- AI 向けのルールの本体を `AGENTS.md` に置き、`CLAUDE.md` はそれを読み込むだけにする。
- AI は Issue に着手する前に自分を担当にし、ほかの人が担当の Issue には手を出さない。順番がある Issue は本文に `Depends on #番号` と書く。
- AI が人に聞くのは「体験が大きく変わる」「取り消せない・お金や外部アカウントが絡む」「要件の矛盾や大きな抜け」のときだけ。それ以外は自分で決めて PR に理由を書く。小さくて戻せるものは作って見せる。小さな質問は PR・Issue のコメントで聞き、複数人で決めたいことや理由を残したい判断は「要相談」の Issue か PR に書く。
- ふつうの変更は PR に書いた試し方で見てもらう。大きな画面変更・音や動画・複数人で決めたいことは、PR とは別にまとめて見てもらう（道具や置き場所は決めない。008）。
- 重複した関数や使われていないコードは、AI が小さい専用の PR で整理する。動きを変えない小さな整理は Issue なしでよい。
- docs は書き換えと削除を前提にする（決定を変えたらそのファイルを書き換える、直ったハマりどころは消す）。

## 理由

- Codex など Claude 以外の AI は `CLAUDE.md` を読まず、`AGENTS.md` を読む。メンバーがどの AI を使っても同じルールで動くようにするため。
- 5人の AI が同時に動くと、同じ Issue を別々に始めてしまう。担当者を先に付ければ、ファイルの担当決めをしなくても重複を防げる。
- 「Issue に書いていない仕様はすべて質問する」だと、細かいことまで人に返ってきて、人の負担と待ち時間が増える。人が持つべき判断（体験・設計）だけを聞くようにした。
- docs が追記だけで増えると、古い情報を AI が読んで間違える。
- マージを人が行うルール（001）は変えない。

## 検討したほかの案

- CLAUDE.md と AGENTS.md に同じ内容を書く：二重管理になり、片方だけ更新されてずれる。
- ファイル単位で担当を決める：AI の動きを縛りすぎる。コンフリクトは PR で解消すればよい。

## 影響（変わること・注意すること）

- 「要相談」ラベルは、人の判断を待っている Issue と PR に付ける。
- `docs/decisions/README.md` の「決定を変えたときは新しいファイルを足す」ルールは、「そのファイルを書き換えて『変更：』を1行足す」に変わる。使われなくなった決定は消さず、「廃止：」を書いて残す。
