# ChatGPT（Dot・Codex）から NEMU を使う

NEMU の仕事は、Claude（NEMU の中の AI）と ChatGPT の Dot・Codex で分けている（`docs/decisions/010-llm-in-review-bot.md`）。

| だれ | 仕事 | どう動く |
|---|---|---|
| Claude（NEMU の中） | 意図をくみ取る仕事：PR の要約（#21）、感想 → Issue（#22）、Issue の分解と担当提案（#24） | NEMU が自分で呼ぶ |
| Dot（ChatGPT、決まった時間に動く） | 厳密さが要る仕事：朝夕のダイジェスト（#23、事実だけ）、放置ブランチ・Issue の見回り（#25） | GitHub を読んで、NEMU の道具で Discord に書く |
| Codex | PR の安全チェック（シークレットの混入、テスト・型、ルール違反） | 結果を NEMU で PR のスレッドに書く |

Discord への窓口は全部 NEMU。Dot や Codex は Discord に直接書かない。

## 1. ChatGPT に NEMU をつなぐ（1回だけ）

> まだ本物で試していない（2026-11-28）。つないでみて違ったら、この節を直す。

1. ChatGPT の「設定 → アプリとコネクタ（Apps & Connectors）→ 詳細設定」で **開発者モード（Developer mode）** をオンにする。Business ではワークスペースの管理者が先に許可する必要があることがある。
2. 「作成（Create）」から新しいコネクタを足す。
   - 名前：`NEMU`
   - MCP サーバーの URL：オンボーディング資料にある NEMU の URL（`https://…/mcp/<鍵>`）。**鍵入りなので、チャットや Issue に貼らない**
   - 認証：**なし（No authentication）**。鍵は URL に入っている
3. 新しいチャットで NEMU をオンにして「NEMU の list_reviews を呼んで」と頼み、スレッドの一覧が返れば OK。
4. Dot にも同じコネクタを使わせる（Dot の設定でアプリを許可する）。GitHub を読むために、ChatGPT の GitHub コネクタも Dot に許可する。

書き込む道具（`post_digest` など）は、呼ぶたびに ChatGPT が確認を求めることがある。決まった時間に動く Dot で確認が出て止まるなら、確認を省ける設定があるか見る（未確認）。

Codex（CLI・IDE）は `tools/review-bot/README.md` の「各自のエージェントで使う」で登録する。

## 2. Dot に頼む：朝夕のダイジェスト（#23）

Dot に次の文をそのまま渡して、予定（毎日 8:00 と 18:00、日本時間）を作ってもらう。

```text
毎日 8:00 と 18:00（日本時間）に、GitHub の noriakiumei/OyasumiDopaTec._2026P2HACKS の動きを、
前回（8:00 なら前日の 18:00、18:00 ならその日の 8:00）から今までの分だけ集めて、
NEMU の post_digest で Discord に書いてください。

書くこと（その期間に当てはまるものだけ。無い見出しは書かない）
- マージされた PR：#番号 タイトル（作った人の @GitHubログイン名）
- 新しくできた Issue・閉じた Issue：#番号 タイトル
- レビュー待ちの PR：#番号 タイトル、レビューを頼まれている人の @ログイン名、待っている日数
- 3日以上動きの無い、開いている Issue と PR：#番号 タイトル、担当の @ログイン名、最後に動いた日

決まり
- 最初の1行だけ、チームのマスコット「ネム」（眠そうだけどハイテンション）のあいさつを短く書いてよい（例：「おはよ〜……まだ眠い💤 朝のまとめだよ」）。そのあとは事実だけ。
- 事実だけを書く。「詰まっている」「遅れている」などの解釈や、おすすめは足さない。
- 番号・人・日付は GitHub の値をそのまま書く。分からないものは書かない。
- 1項目1行。全体で 1500 文字まで。多いときは新しい順に並べて「ほか N 件」とまとめる。
- title は「11/28 朝のダイジェスト」「11/28 夕方のダイジェスト」の形。
- 期間内に何も動きが無ければ、何も書かない。
```
